**F4 — arch §6.5 `audit_log.action` enum is missing three values used by this feature.**
Arch §6.5 enumerates `audit_log.action ∈ {enrolled, revoked, sidecar_restart, bridge_toggle, export, import, wipe}`. This feature's `data-model.md` §4 + `tasks.md` (T035/T035a/T036/T039/T074) write three values not in that enum: `config_error`, `sidecar_healthy`, `sidecar_unhealthy`. The SQLite schema is permissive (`TEXT NOT NULL`, enum lives in a comment) so the drift would not fail at insert time — `stargate-redteam` is the only backstop. T018 amends arch §7 and §10.1 in lock-step for FR-015/AUTH_REQUIRED, but no analogous task amends arch §6.5.

*Fix*: Extend T018 (or add T018a) to amend arch §6.5's `action` enum comment with the three new values used here, and add a cross-reference from the comment to `data-model.md` §4 as the per-feature extension point. Optionally remove `sidecar_restart`/`bridge_toggle` from the v1 enum if they're not used in v1.

**E1 — FR-016 promises `tests/contract/tor/` coverage that no task realises.**
FR-016 L438–449 says `tests/contract/tor/` covers four invariants:
1. SOCKS5h handshake on the rendered config
2. SOCKS5 connection to a known-reachable onion service
3. Rejection of username-less requests under `IsolateSOCKSAuth`
4. `GETINFO version` under cookie auth

The only tasks landing files under `tests/contract/tor/` are **T019b** (port_exposure_test.go — *not* in FR-016's list) and **T062** (control_port.go — a helper, not a test). The four promised invariants are *partially* covered elsewhere: T032 in `torrc/` runs `GETCONF SocksPort`; T033 in `integration/` does an onion connect; T058 in `torrc/` tests isolation effect. None of those satisfy the literal FR-016 surface promise for `tor/`. The `GETINFO version` under cookie auth check is entirely uncovered.

*Fix*: Either (a) add three to four contract-test tasks under `tests/contract/tor/` to cover the FR-016 invariants, OR (b) amend FR-016 to match the actual partition — move the onion-connect promise to `integration/` (citing T033), move IsolateSOCKSAuth username-less rejection to `torrc/` (citing T058), and drop or schedule the `GETINFO version` check. The current state ships a contract surface where the spec's claimed gate doesn't exist.

**F5 — SC-003 capture filter has three different shapes across spec, T034a, and quickstart.**
SC-003 (`spec.md` L545–549) specifies "capture filter `dns and frame contains '.onion'` returning zero packets across both interfaces" — that's **Wireshark display-filter syntax** (`frame contains` is a Wireshark expression, not BPF/tcpdump). The quickstart's "SC-003 — No DNS leak" check (`quickstart.md` L186–192) uses `sudo tcpdump -i lo -i any 'port 53'` — a **BPF filter on port 53** ("any DNS packet" vs "any packet containing the literal `.onion`"). The two also disagree on interfaces: spec says "lo + egress NIC" explicitly; quickstart says `-i lo -i any` (`any` captures everything including lo). And T034 (per-PR gate) uses `gopacket` with a third filter shape ("A/AAAA/MX containing `.onion`"). Three different filter shapes for one invariant.

*Fix*: Pick one canonical filter (the gopacket byte-substring scan from T034 is the most direct expression of the invariant) and align quickstart and SC-003 to reference it. Add an explicit cross-reference in quickstart Step "SC-003" to T034's filter so the operator sees the same shape as CI.

**C3 — FR-018 enumerates only `enrolled`; `revoked` and `config_error` are implementation-required but unspec'd.**
FR-018 prescribes "emit a single audit-log entry of kind `enrolled` for each new label" — only `enrolled`. But the diff-load semantics in `data-model.md` §4 + T035 + T035a require emitting `revoked` (when a label disappears) and `config_error` (with three sub-kinds `parse`/`validation`/`io`). FR-018 also fails to mention the missing-file-writes-no-row rule documented in data-model.md §4 and T035a case (i). An implementer reading only FR-018 would build something less complete than what the data-model and tests assume.

*Fix*: Extend FR-018 to enumerate all three token-action audit kinds (`enrolled`, `revoked`, `config_error`) and reference `data-model.md` §4 for the full schema (including the missing-file exemption). The spec is the operator-facing contract; the data-model can be the schema source-of-truth, but the spec must enumerate the kinds so reviewers can verify them against Principle III (no per-request data) without chasing the data-model.

**C4 — Quickstart "Load Temporary Add-on" wording leads with non-supported `.zip` path.**
Quickstart Step 3 (L116–119) says "Click **Load Temporary Add-on**. Select `dist/stargate-extension.zip` (or its inner `manifest.json`)." Firefox's `about:debugging` "Load Temporary Add-on" canonically requires either an unpacked `manifest.json` or a signed `.xpi` — a raw `.zip` is **not** an officially-supported input. The parenthetical clarification provides the working path, but the primary instruction reads as if the `.zip` will load directly. The SC-001 5-minute walkthrough hinges on this step working first-try; a user who selects the `.zip` and hits a non-actionable Firefox error has burned their MVP budget.

*Fix*: Reword Step 3 to lead with the unpacked-manifest path: "extract `dist/stargate-extension.zip` to a temporary directory, then **Load Temporary Add-on** and select the extracted `manifest.json`." T077's walkthrough is the natural place to verify the wording works against a real Mullvad Browser.
