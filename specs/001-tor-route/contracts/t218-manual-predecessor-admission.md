# T218 manual predecessor admission — current scope and preserved history

## Current scope — 2026-10-16

The [qualification boundary](qualification-boundary.md) Q3–Q6 supersedes the healthy same-candidate
reuse, repeated authority-writer revisions and BEFORE/AFTER quota-image bridges below. It retains
trusted manual completion observation, literal bounded closed input, stale/concurrent refusal,
independent historical identities, immutable evidence, cumulative capacity and every fixed safety
cap. A new candidate uses the same exclusion domain; it cannot bypass pending or reset capacity.
The first candidate and subsequent candidate handoffs require their respective independently
observed bootstrap/authorization/predecessor completion. This is a required source target, not an
implemented carrier/schema or native approval. Tickets and source must be reconciled before use.

## Terminal success and the trusted external decision

A predecessor is complete only when the independent invoker actually observed its original Go process normal exit 0, exact stream EOF, complete bounded output, descriptor closure, source/state/authority/directory readback and original deadlines, AND the invoker command itself finished successfully after publishing and checking its receipt. For bootstrap and the separately invoked authority writer, the same actual command exit/output/readback/close and observer-command completion are required. An observer receipt visible on disk is factual evidence to inspect; it cannot certify the publisher or invoker finished successfully. A digest, settled state, old PID absence, or passing source test cannot establish missing observation.

A trusted maintainer must personally have the actual successful command result and the exact reviewed immutable evidence. The maintainer's next deliberate invocation supplies an explicit per-invocation attestation of that observed completion. Neither Go nor Python creates or supplies this decision automatically. The native final human observation cannot be replaced by root/subagent automation; private fixture controllers emulate the external authority solely to test enforcement and are labelled fixture evidence.

The decision's authoritative event is the trusted maintainer's deliberate submission and Go's validation under the stable scope lock. It does NOT claim that the submission command has itself already completed; it attests only to past commands independently observed by the maintainer. Thus a later failure of the new invocation cannot retroactively certify its own completion or authorize a further invocation. Another human decision is needed after every healthy predecessor. Missing, failed, late, uncertain or unavailable command observation forbids the decision; no recovery/re-sync/repair route exists here.

The cooperative same-UID/trusted-maintainer boundary remains explicit. CLI syntax cannot prove a human was present, authenticate backend expertise, or defeat a malicious same-UID actor. The actor is trusted as in the existing explicit maintainer authority gate; the support contract forbids unattended decision generation. If stronger cryptographic or malicious-same-UID authenticity is required, this design is not approval of that new guarantee.

## Concrete carrier, closed bytes and admission

Carrier: a new explicit launcher argument `--manual-predecessor-admission=<canonical-ASCII-JSON>` is a literal invocation value, never a path/env-selected decision file or automatically reconstructed value. It is bounded to 1024 bytes, exact closed schema, no duplicate keys, canonical encoding, and has these keys: schema=t218-manual-predecessor-admission-v1; domain=native|fixture; operation=authorize|attempt; scope_sha256; enrollment_generation; current_authority_revision; current_authority_sha256; next_operation_id; bootstrap_bundle_sha256; authority_bundle_sha256; settlement_bundle_sha256; observed_complete=true. IDs are exact bounded authoritative format, numeric revision is unsigned nonzero, hashes are lowercase SHA256. All-zero authority/settlement reference is allowed ONLY in the initial cases explicitly defined below; it is never a missing-evidence fallback. The authority and settlement references are independent: an immutable G1 settlement never needs to acquire a reference to a future G2 writer. It is not a bearer credential. No new network, notification, supervisor, cleanup actor, mutable terminal ledger or persistent approval file exists.

Python treats this as an externally supplied typed input and may transmit it only in the existing bounded launch record; Go validates independently. The fixed six-frame count/order/4096-byte launch limit/17,408-byte total limit do not increase. Only a directly invoked explicit maintainer authority-writer command can transmit an authority-related decision. Python never invokes that writer automatically or grants scope/host authority. Fixture roles accept only fixture-domain decisions and cannot become native-eligible.

Under the existing stable no-follow lock, Go independently rereads the latest authority, enrollment, exact reservation and evidence-root identities; checks the decision's domain/scope/generation/operation/next-operation/current-revision; selects the independent bootstrap, current-authority and last-settlement bundles solely from those pinned facts; and opens ONLY their schema-derived basenames in the pinned root. It validates the explicit digest references, original source/runner/binary/helper/toolchain identities and reviewed past results, successful observed child/stream/descriptor/deadline facts, and the transition mapping below. Historical source/binary identities stay bound to the actual original predecessor and its reviewed result; the new invocation independently requires its current authority-approved source/build identity. Never substitute current source hashes for historical ones. Decision input never selects arbitrary paths or clears pending. A G1 decision refuses after G2, even if scope/generation remain the same. An authorize decision cannot enter readiness; an attempt decision cannot append authority. Copying a decision for another operation/next-operation ID refuses. Once pending is durably committed, second/concurrent attempts and authority updates refuse.

### Closed persistent-state and reference mapping (A1 closure)

Let B be the immutable completed bootstrap bundle, Wj the immutable observed authority-writer bundle for current revision Gj, and Sk the immutable completed settlement bundle for the last healthy attempt. B never references a future writer. Sk retains the original authority Wold and original full settled bytes/inode; it is never rewritten for Gj. A literal decision supplies B, Wj and Sk as independent references. A next reader opens at most these three headers, without recursive reference traversal or scanning older history. The current bounded authority-history bytes and predecessor snapshots may be checked within their pinned existing/derived limits; no unbounded chain scan is permitted.

Wj binds its original Go-writer command/operation ID, source and successful observation facts, the exact prior/latest authority revision bytes, B, the last completed settlement Sk (or the initial idle projection), and BEFORE/AFTER full reservation snapshots and inode identities for its serialized capacity accounting. It also retains the immutable original Sk digest when earlier successful writer accounting already changed the current metadata. BEFORE is checked against the previous independently completed W header and the unchanged Sk projection before any new writer operation. AFTER is the exact current reservation image following this writer's quota charge. Only capacity counters/accounting-operation identity may differ; state, enrollment, last settled attempt/owner/source/deadlines, pending/settlement proof and resource identity fields remain identical. The Go authority writer is an existing distinct administrative role: it may precharge capacity under the same lock but never writes a lifecycle transition, clears pending, settles effects, creates readiness effects or replaces the Go owner. This narrow accounting permission is explicitly included in the coordinated T218 amendment, not assumed from old code.

The reader uses a named immutable settlement projection plus exact quota-image identity, never a blanket ignored-field comparison: if Sk is the latest settled image and no later accounting changed it, current bytes/inode equal Sk's captured image. If later writer accounting changed it, current bytes/inode equal the latest completed Wj AFTER image, while Wj's copied immutable settlement projection and reference equal Sk. Any other changed field/image refuses. Sk's actual old full bytes/inode remain retained in immutable evidence even when canonical reservation.json is atomically replaced for quota accounting. The writer's accepted AFTER quota image is not settlement authority; it is separately witnessed administrative evidence.

Every supported operation after initial bootstrap requires a fresh deliberate decision that attests to ALL the named already-completed prior facts, not just a schema bit. The trusted maintainer may not replay a decision after a failed/unknown operation. An invocation argument cannot machine-prove truthful human observation; lying/replay contrary to that explicit trusted-actor premise is outside this guarantee, as in v1. Software still rejects every observable missing/stale/substituted/pending/quota-image mismatch; it does not claim a failed pre-publication syscall can reliably persist its own failure marker. Private controllers must withhold the decision on every injected uncertain history and separately test the observable stale/image/refusal paths. Bootstrap/current-writer facts and original settlement are thereby independent inputs rather than recursively self-certified receipt chains.

## Historical identity and immutable evidence storage

Reuse the existing private-candidate/evidence concept outside the disposable workspace and active effects namespace. Provision one authority-pinned mode-0700 single-UID evidence root at `<pinned-home>/.local/state/stargate/t218/evidence`; bind absolute canonical path, UID, device/inode and policy limits in enrollment/authority. Only explicit bootstrap may create it. Live admission never provisions, rotates, repairs or substitutes missing enrolled evidence state.

Each predecessor bundle is immutable, no-follow, mode-0600, link count one, identified by exact kind/attempt/revision and digest. Its bounded header (4096 bytes) binds original pending and settled full-byte identities/digests, enrollment/authority, original owner's PID/start, source/build/helper/toolchain identity, actual observer Wait/EOF/close/deadline facts and exact proof/receipt references. Historical effects-directory device/inode/UID/mode/link identity is captured while the original owner/observer retains its FD; a fresh admission compares the no-follow path and held FD to that historical identity and independently verifies exact absence. Empty same-path directory alone is insufficient. A manually attested summary cannot replace the underlying required resource evidence.

Keep existing raw private receipt cap (one MiB for established fixture reports; final native receipt retains its approved own cap), stream/source/proof limits and original deadlines. The envelope contains exact file identities and sizes, no caller-selected files, and a finite reference list: bundle header, original owner output, observer receipt, original settled record, settlement proof and authority/bootstrap evidence references. Every component has an explicit existing or derived maximum in the implementation plan before tests; proof/settled/header remain <=4096. No native limit increases are authorized here.

For aggregate storage, precharge the worst-case byte/file/inode footprint of each supported evidence-producing operation in the EXISTING reservation metadata under the stable lock, durably before any producer can create its bounded bundle. This is quota accounting in the existing admission reservation, not a separate mutable pending/terminal lifecycle ledger. The initial bootstrap/authority allocation is charged in the provisioned enrollment manifest; later pending records reserve one complete attempt envelope, including the externally produced receipt and all temporary files that can coexist. Charges are conservative and monotonic across healthy settled reuse; no refund, deletion, scanning old history, or reconstruction after failure. Failed/unknown charge publication refuses. Immutable records remain preserved. Configured positive byte/file/inode ceilings are authority/enrollment-pinned and validated against the sum of the concrete maxima; actual producers enforce the reserved per-file limits and cannot exceed the charged envelope. Capacity exhaustion refuses before the next pending/effect, without imposing an arbitrary fixed number of attempts. Bootstrap/writer history allocation must be accounted for before every additional revision; this accounting is serialized with the existing authority transaction and cannot grant admission on its own.

Admission looks up the three independent literal references for bootstrap, current authority writer and last settled predecessor (maximum three headers); it does not inspect arbitrary older bundles. A→B→C healthy use retains A and B while C opens only its bounded immediate predecessor and authority/bootstrap references. Exact active effects membership remains free of archived proofs. Arbitrary additional files in the active namespace, substituted historical directory/evidence, missing/over-limit evidence, stale grant and uncertain storage refuse. The whole implementation class includes each bootstrap/writer/owner/observer producer and temporary publication path; no caller-only quota counter is credited as complete enforcement.

## Implementation and evidence gates

Root authors the exact implementation plan before tests. It must specify every closed per-kind schema, the complete immutable settlement projection and only permitted quota fields, all producer/temporary write sites, numerical byte/file/inode maxima and conservative overflow-safe capacity sums including authority growth and transient quota replacement. Capacity definitions must be pinned in bootstrap/enrollment/authority and validated before any producer starts. No plan-only quota count is implemented enforcement.

Luna6/high implements only approved source slices in the existing T218 tree. Fresh Astra/high and Luna6/high review each exact tests-only batch before affected execution and the resulting exact source before integration. Each new repair keeps actual behavioral RED before code and identical GREEN selectors afterward. Missing tooling/import/API/compiler/invalid fixture is setup, never RED. Existing correct refusal remains retrospective and cannot be weakened to manufacture RED. Executed consumer-establishment evidence proves only that establishment behavior. Final full T218 requires actual native qualification, exact source-plus-receipt review and its separate host authority; human decisions cannot be supplied by agent automation at that live gate.
