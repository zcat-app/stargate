# Contract — Privacy-Safe Error Template (Tor-route scope)

**Status**: Phase 1 contract document

**Scope**: instantiates architecture spec §10's privacy-safe error
future HTTP renderer format for these error codes:

- `ROUTE_DOWN` (502) — Tor sidecar unreachable or unhealthy.
- `ROUTE_REFUSED` (502) — sidecar accepted SOCKS5 but refused the target.
- `ROUTE_TIMEOUT` (504) — upstream did not respond in time.
- `AUTH_REQUIRED` (407) — bearer-token missing/invalid (introduced by
  this feature; arch §10.1 amended in lock-step).

This is a **renderer-only future HTTP format** for Tor-labelled errors. The Tor
port 8881 does not emit it: authenticated SOCKS5 failures use RFC 1928/1929
binary replies; HTTP first byte `C` closes silently before auth or dial.
T173 removes the HTTP parser and migrates its active transport/renderer coverage. No browser-visible HTML failure is promised for Tor.
Other routes require their own reviewed ingress contracts.

**Source**: architecture spec §10.1 (codes), §10.2 (body template),
§10.3 (contract test pattern), FR-009.

## Future HTTP renderer wire format (no Tor-port ingress)

### Status line

```
HTTP/1.1 <CODE_STATUS> <REASON>
```

| `{CODE}`           | `CODE_STATUS`       | `REASON`                       |
|--------------------|---------------------|---------------------------------|
| `ROUTE_DOWN`       | `502`               | `Bad Gateway`                   |
| `ROUTE_REFUSED`    | `502`               | `Bad Gateway`                   |
| `ROUTE_TIMEOUT`    | `504`               | `Gateway Timeout`               |
| `AUTH_REQUIRED`    | `407`               | `Proxy Authentication Required` |

### Response headers

Exactly these four headers, in this order, no others:

```
Content-Type: text/html; charset=utf-8
Content-Length: <body length in bytes>
Cache-Control: no-store
X-Stargate-Error: <CODE>
```

`<CODE>` is one of `ROUTE_DOWN`, `ROUTE_REFUSED`, `ROUTE_TIMEOUT`,
`AUTH_REQUIRED`.

**Forbidden** in any response under this contract:

- `Server` header.
- `Via` header.
- `X-Forwarded-*` headers.
- `Proxy-Agent` header (407 responses do NOT include it; we do not
  identify the proxy implementation in the response).
- Any sidecar version string.
- Any Tor circuit identifier.
- The destination hostname or port.
- The offered token or its hash.

### Response body

```html
<!doctype html><meta charset=utf-8>
<title>Stargate: route unavailable</title>
<h1>Route unavailable</h1>
<p>The {ROUTE_LABEL} route is currently not serving requests.</p>
<p>Code: {CODE} · Reference: {LOCAL_REFERENCE_ID}</p>
<p>See the admin dashboard for details.</p>
```

Permitted substitutions:

- `{ROUTE_LABEL}` = `Tor` for this feature.
- `{CODE}` = one of `ROUTE_DOWN`, `ROUTE_REFUSED`, `ROUTE_TIMEOUT`,
  `AUTH_REQUIRED`.
- `{LOCAL_REFERENCE_ID}` = a 16-character lowercase-hex string derived
  from a 64-bit random value generated at response-build time. It is
  **not derived from request data** — never from the token, the
  destination, the timestamp, or the source port. The value is
  generated by `crypto/rand.Read(8)` and hex-encoded.

The body MUST be byte-for-byte the literal template above, with the three
permitted fields substituted. No whitespace variation, no additional
elements, no inline CSS or JS. Line endings are `\n` (single LF), not
CRLF — this matches the template literal stored as a Go string in
`data-plane/internal/errortpl/template.go`. (The renderer that
substitutes the fields will live in the sibling `render.go` —
T048 / T071.)

## Leak-corpus invariant

The contract test pattern from arch §10.3 applies. The curated leak
corpus for this feature includes at minimum:

- `tests/contract/error-template/leak-corpus.txt` entries:
  - `duckduckgogg42xjoc72x3sjasowoarfbgcmvfimaftt6twagswzczad.onion`
    (the SC-001 / SC-002 reference target).
  - Every synthetic `.onion` string used in the SC-002 100-domain corpus.
  - The data plane's egress IP captured at test time.
  - A representative Tor exit IP from the consensus at test time.
  - The string `Server: tor/`, `Tor`, `Tor Browser`, `Mandrel`, `Quarkus`,
    `Hibernate`, `SQLite` (would-be version-string fragments).
  - The string `panic:`, `goroutine`, `stack trace`, `at line`
    (would-be backtrace fragments).
  - Every token used in the test run (a random hex string generated by
    each test case and added to the corpus for the duration of the
    test).
  - Every SOCKS5 control-port event captured during the test.

Renderer contract tests scan every byte of the complete response — the
status line, headers and body — for every checked-in corpus entry and each
case's synthetic destination/token values. The literal `Tor` corpus entry
has one narrow exception: exactly one occurrence is required at the fixed
`{ROUTE_LABEL}` position in the body (`The Tor route`); any other occurrence
fails. All other corpus hits fail. The egress IP and captured Tor control-port
events are live-stack-only inputs because direct renderer tests create neither
an egress path nor a Tor control connection; they remain inputs to the live
stack corpus/evidence, not omissions from renderer coverage.

## Renderer tests (`tests/contract/error-template/`)

T173 converts the AUTH_REQUIRED ingress-driven tests to direct production-renderer calls.
Preserve byte-exact status, four-header order/absence/length, body substitution,
reference-ID shape/freshness/only-variable-bytes and full response leak scans.

T071 implements the three route renderers and positive format assertions for all four codes,
including T068's byte-exact body cases and T069's reference-ID uniqueness/distribution and
repeated-call freshness checks. Each code receives 1,000 sequential samples; the coarse
per-position digit bound detects gross bias but is stochastic evidence, not proof of
independence or unlinkability. These tests and implementation are one atomic red-before-green
change; T068/T069 are superseded deferred records, not prerequisites that must pass first.
This maintainer-authorized T173 refinement supersedes T172's all-four-code migration row
without changing its historical approval or weakening the future format contract.

No test here claims an HTTP response is reachable from Tor port 8881. Supported SOCKS auth
and route failures, plus HTTP refusal, remain covered under `tests/contract/socks5/` and the
T173 real-socket regression. Every migrated/deleted test has an explicit invariant mapping.

Adding a new error code to the data plane requires adding a new row to
this contract document AND a new test in `tests/contract/error-template/`
in the same PR.
