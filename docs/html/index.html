Stargate

An open-source, multi-protocol privacy-routing proxy. A browser extension picks the route per request — Tor, I2P, Nym mixnet, or Direct — and the proxy forwards bytes to the appropriate sidecar. Family-shareable, Docker-deployed, privacy-first. Apache 2.0 licensed.

Status: in development. The v1 vertical slice (specs/001-tor-route/) is the active feature. The proxy itself is not yet released. What IS real today: the Constitution, the architecture spec, the threat model, and the developer tooling layer (ticket-driven workflow, agent-CLI bindings, CI). What is NOT real yet: the running proxy, the browser extension, the compose stack, the install path. Pages below flag this honestly per section.

What Stargate is

A privacy-routing proxy. The browser extension is where the user picks the route per request; the proxy is a dumb router that forwards bytes for the port it received them on. The proxy itself does no payload parsing, no TLS termination, no local DNS resolution, no header inspection, no per-request logs, no cover traffic. This is Constitution Principle I and it is binding, not aspirational.

Two processes, distinct lifecycles, gRPC over Unix socket between them:

PlaneLanguageResponsibility
Data planeGo (data-plane/) Network transport, sidecar coordination, per-port routing. Privacy-critical hot path. The "dumb router".
Control planeQuarkus 3.40 LTS on JDK 25 LTS (control-plane/) Admin UI, settings, sidecar lifecycle commands, audit. SQLite for state.
ExtensionJS/TS (extension/) Per-request route selection. First-class target: Mullvad Browser.

Deployment: Docker Compose, three profiles — local (loopback only), lan (WireGuard sidecar), vps (WireGuard/Tailscale tunnel). The proxy refuses to bind a non-loopback interface without a corresponding tunnel sidecar.

Status today

What works right now:

  • Constitution, threat model, architecture spec — all written, all binding.
  • Spec-kit integration (specify → plan → tasks) is wired.
  • 108 tickets for the v1 vertical slice (Tor route) are drafted with structured YAML frontmatter.
  • 11 tickets are done (Phase 1 scaffolding: directory skeleton, Dockerfiles, proto definitions, build tooling).
  • The developer workflow layer (ticket model, run-task.sh, verify.sh, CI mirror) is real.
  • opencode is wired as the primary agent CLI; Claude Code is a stubbed second option.

What does not work yet:

  • The proxy itself. No data-plane code beyond scaffolding.
  • The browser extension. No MVP2 build.
  • The Docker Compose stack for end-user deployment.
  • The install path, the admin UI, the observability stack.
  • Routes other than Tor (I2P, Nym, Direct are v1 scope but not built).

If you are a user looking to install Stargate today: you can't yet. Watch the v1 vertical slice (specs/001-tor-route/). If you are a developer or contributor: the developer guide is the most complete page here and the right place to start.
