Technical reference

Status: substantial. The architecture spec (specs/000-architecture/spec.md) and the Constitution (.specify/memory/constitution.md) are real and binding. This page summarises; those files are the contract.

Architecture at a glance

Two processes, distinct lifecycles, gRPC over Unix socket between them. See the two-plane architecture diagram for the visual layout.

PlaneLanguageResponsibility
Data planeGo (data-plane/) Network transport, sidecar coordination, per-port routing. The "dumb router". Privacy-critical hot path.
Control planeQuarkus 3.33 LTS on JDK 25 LTS (control-plane/) Admin UI, settings, sidecar lifecycle commands, audit. SQLite for state.
ExtensionJS/TS (extension/) Per-request route selection. First-class target: Mullvad Browser.

Constitution Principle I — the dumb router

The data plane is the privacy-critical hot path. It is actively forbidden from:

  • parsing request/response payloads
  • terminating TLS
  • resolving DNS names locally
  • inspecting headers
  • emitting per-request log lines
  • generating cover traffic
  • making outbound connections on its own behalf (only the user's routed request reaches the network)

Routing decisions are made by the browser extension; the data plane forwards bytes for the port it received them on. This is enforced in code (contract tests under tests/contract/) and in review (the stargate-codereview reviewer fails any diff that adds any of the above to the data plane).

The data plane must keep routing if the control plane is unreachable (Principle II). The cold-start cache (dp-snapshot.json, data-model §1.4) holds the last-known-good token generation; the data plane bootstraps from it and serves requests even with the CP down. The control plane re-pushes a fresh generation on reconnect.

Inter-plane contract

Two Unix domain sockets, one per direction:

SocketHosted byOwnerMode
/run/stargate/control.sock Control plane (CP is the server) stargate-cp:stargate-ipc 0660
/run/stargate/dp.sock Data plane (DP is the server) stargate-dp:stargate-ipc 0660

The shared supplementary group stargate-ipc (GID 5100) owns both sockets; both planes are members. Mode 0660 lets each plane connect(2) its dial-direction socket while keeping random unprivileged same-host processes outside the dial surface. Distinct hosting UIDs (stargate-cp 5101, stargate-dp 5102) are defense-in-depth: a compromise of one plane does not yield filesystem-write access to the other plane's state volume.

The gRPC schema is at proto/stargate/v1/{control,events}.proto. Three RPCs in v1:

  • ReloadTokens (CP → DP) — push a new token generation; DP atomic-swaps and persists a fresh snapshot.
  • WatchEvents (CP → DP, server-streaming) — sidecar lifecycle events (STARTED, HEALTHY, UNHEALTHY, STOPPED, CRASHED, RESTARTED).
  • GetStatus (test-only in v1) — aggregate counters. Production caller deferred to the admin-UI feature; a grep regression test (T022) blocks any production code from wiring it before that feature lands.

Sidecar model

Each route has a sidecar: Tor, I2P, Nym, Direct (no sidecar). The sidecars run as compose services alongside the data plane; the data plane reaches each by its compose-internal DNS name (tor:9050, i2pd:<port>, nym:<port>).

Every sidecar image is pinned by sha256 digest per Constitution Principle IV. The Tor sidecar's apt-repo signing key is verified at build time against sidecars/tor/apt-key.fingerprint (ticket T014, FR-015). The docker-socket-proxy aux container (audit-trail at SECURITY-DECISIONS.md) is the only service that mounts /var/run/docker.sock, exposed as a GET-only filtered HTTP API.

Privacy-critical surfaces (where reviewers focus)

The Constitution calls out five categories of code where tests must be written first (Principle VII, no AI exception) and where stargate-redteam hunts at every release:

SurfaceWhat bitesTest gates
DNS resolution Local resolver leaks the destination hostname. T034 (DNS leak), T034a (SC-003 measurement), T034f (consensus egress)
Routing decisions Wrong route selected; bytes leak to unintended network. T022 (transport invariants), T025a (log allowlist)
Header handling HTTP CONNECT target host logged or inspected. T025a, T027 (AUTH_REQUIRED)
Authentication Token comparison short-circuits; argon2id timing leak. T025 (slot-invariance), T025c (counter side-channel)
Sidecar contracts Rendered torrc drifts; sidecar exposes ports. T019b (Tor port exposure), T019c (proxy lockdown), T029–T032 (torrc byte-for-byte)

Technology choices

Go 1.26 (data plane)
Pinned via the toolchain directive in data-plane/go.mod. Static analysis: go vet, staticcheck, gosec — all wired into scripts/verify.sh.
Quarkus 3.33 LTS on JDK 25 LTS (control plane)
Pinned via <maven.compiler.release>25 and the Quarkus platform BOM. LTS-to-LTS upgrades follow the same documented process as sidecar image bumps (Constitution Principle IV). Native-image is not in scope for v1 — the JVM build is what the v1 vertical slice exercises; native lands with the first release tag.
SQLite (control-plane state)
File-based; no separate database process. Migrations via Flyway (ticket T012). The audit log is row-level append-only.
JSpecify + Error Prone + NullAway (control plane, post-T081)
Compile-time nullness enforcement. app.zcat.stargate packages are @NonNull by default; genuinely-nullable edge types declare @Nullable. The build fails on a missing or incorrect nullability contract. This is the machine-checked complement to the "validate at edges, trust inside" doctrine (see ticket T081).
Docker Compose (deployment)
Three profiles: local, lan, vps. Every external image is digest-pinned. See the advanced guide for the per-profile topologies.

Build reproducibility

The data-plane binary is built byte-reproducibly: -trimpath -buildvcs=false -ldflags="-buildid=" CGO_ENABLED=0 (ticket T004). The release-cadence reproducibility tests (tests/reproducibility/) build the binary, the JAR, and the extension zip twice in clean containers and cmp the outputs. A non-reproducible release tag fails the release.
