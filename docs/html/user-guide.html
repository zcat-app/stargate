User guide

Status: not yet shipped. The Stargate proxy is still in development (v1 vertical slice: specs/001-tor-route/). There is no installable artefact yet. This page is the placeholder for the stupid-proof end-user guide that will land alongside the v1 release. What follows is the outline of what the page will cover, plus the developer setup that works today if you want to run from source.

What this page WILL cover (when v1 ships)

  1. Install — one-line Docker Compose bring-up against the digest-pinned release images. No manual docker pull; Compose verifies the digests against compose/env/local.env.example.
  2. First-time setup — scripts/stargate init --profile local generates the ed25519 plane keys, runs the bounded healthcheck wait, and prints a status table with the enrollment code you paste into the browser extension.
  3. Browser extension install — load the stargate-extension.zip into Mullvad Browser (or LibreWolf) as a temporary extension; enter the enrollment code; verify the per-tab route indicator lights up.
  4. Start / stop / restart —
    • scripts/stargate start — bring up the stack.
    • scripts/stargate stop — graceful drain, then stop.
    • scripts/stargate restart — stop + start, preserving state (token generation, audit log).
  5. Picking a route — clicking the extension icon per tab, choosing Tor / I2P / Nym / Direct; the indicator confirms the active route.
  6. Troubleshooting — the four exit codes from scripts/stargate (10/20/30/40/50), what each means, what to do.

What works today (developer setup)

If you want to look at the code or run partial pieces before v1 ships, the developer path is real today:

# 1. clone
git clone https://github.com/<org>/stargate.git
cd stargate

# 2. data plane (Go 1.26)
cd data-plane && go mod download && go build ./... && cd ..

# 3. control plane (JDK 25 + Quarkus 3.33 LTS)
cd control-plane && ./mvnw -B verify -DskipTests && cd ..

# 4. verify the tree is green
bash scripts/verify.sh

See CONTRIBUTING.md §Development environment for the full prerequisites list (Go version, JDK distribution, Docker, Mullvad Browser) and the developer guide for how the ticket-driven workflow operates.

What is NOT in this guide

  • Threat model — see THREAT-MODEL.md for what Stargate does and does not protect against, per route and per deployment profile. This guide covers how to use; the threat model covers what it gets you.
  • Admin operations — upgrade, observability, backup/restore land in the admin guide.
  • Advanced routing rules — per-site route policies, custom SOCKS5 routing, etc. land in the advanced guide.
