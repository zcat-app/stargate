## Summary

T092 is a privacy-critical **spec/contract amendment** (no production Go/Java
request-path code in the diff). It retires the Argon2id bearer-token verifier
(sol-review B5: unbounded memory-DoS) for `HMAC-SHA-256(pepper, token)` with a
single shared install-time pepper, adds a persisted generation record +
`APPLY_STATUS_STALE_GENERATION` reconciliation handshake (sol-review M1), and
narrows failure semantics so a missing/unreadable/invalid/unparseable
`tokens.yaml` does NOT call `ReloadTokens` (DP keeps last-known — Principle II).

every leaky surface (snapshot, RPC, logs, audit, export). The
HMAC-computed-once + ConstantTimeCompare-against-every-verifier construction
preserves slot-independence. The failure semantics protecting Principle II are
correct in the four authoritative locations. The §5.14 residue is honestly
modeled. **Verdict: CLEAN** — zero Blocker/Major. One Minor (doc consistency,
fixed post-review), two Info.

## Findings

### Minor m1 — `data-model.md §4` stale parenthetical contradicted amended failure semantics — FIXED

- **Where**: `specs/001-tor-route/data-model.md` §4 audit-log `config_error` row.
- **What**: §4 said the missing-file case makes the CP "proceed with an empty
  token list" (the retired M1 behaviour: revoke-all on failure). §1.1 row 4
  (amended) had also lumped "missing" with "unreadable" for the audit row,
  contradicting §4's first-boot no-row exemption.
- **Implicates**: Principle II (the silent-revoke-on-failure bug M1 was written
  to eliminate); doc consistency with acceptance #4.
- **Remediation (applied post-review)**: §4 parenthetical rewritten to the
  amended semantics (do NOT call `ReloadTokens`, DP keeps last-known); §1.1
  row 4 split into Missing (first-boot, no audit row) vs Unreadable (`io` row)
  + Unparseable/invalid (`parse`/`validation` row) — all three share the
  "do NOT call ReloadTokens" failure semantics; only explicit `tokens: []`
  revokes all. Non-authoritative prose now agrees with FR-018 / §1.6.

### Info i1 — `configured_tokens.last_seen_hour` has no update path yet

- **Where**: `data-model.md` §1.9; `V001__init.sql`; arch §6.6.
- **What**: the column is hour-bucketed but no RPC reports per-label auth
  activity to the CP today (deferred-feature placeholder; mirrors the
  pre-existing `enrolled_devices` pattern). Not a leak (hour-bucketed, CP-side,
  never crosses the RPC). Flagged so a future per-label auth-report RPC, if
  added, gets a Principle III review (per-label activity is per-user metadata).

### Info i2 — §5.14 could name the LAN/VPS profile explicitly

- **Where**: `THREAT-MODEL.md` §5.14.
- **What**: the pepper now lives in the DP's process memory (the DP computes
  `HMAC(pepper, candidate)` per request), unlike the retired Argon2id design.
  DP compromise already grants full traffic exposure (§2.6), and the pepper
  alone neither forges a token nor grants access (128-bit brute-force
  infeasible) — so the residue is additive, not multiplicative. Optional: add a
  one-line §5.14 note mirroring §5.13's "under a future LAN/VPS profile … MUST
  be re-reviewed" caveat.
