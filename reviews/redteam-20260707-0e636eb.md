### Info

#### I1. `notatoken` length miscounted in code comment and ticket body
- **Where**: `tests/contract/error-template/auth_required_test.go:81`
  (code comment "10 chars ≠ 32") and
  `specs/001-tor-route/tickets/T027-…md:231` (ticket body "12 chars")
- **What**: The string `"notatoken"` is 9 characters
  (n-o-t-a-t-o-k-e-n). The code comment at line 81 claims "10 chars"; the
  ticket §Analysis redteam scope claims "12 chars". Both are wrong; the actual
  length is 9.
- **Implicates**: Documentation accuracy only. No privacy or correctness
  impact — the malformed token is rejected by the `^[0-9a-f]{32}$` syntactic
  gate regardless of whether it is 9, 10, or 12 chars (it fails both the
  length and the charset gate at any of those lengths). The leak-corpus scan
  operates on the exact bytes of `malformedToken`, not its stated length.
- **Remediation**: Correct the comment to "9 chars ≠ 32". Optionally also
  correct the ticket body (out of code scope; the ticket is metadata).

#### I2. Body-template regex accepts an extra trailing LF beyond the actual
       `errortpl.Template` literal
- **Where**: `tests/contract/error-template/auth_required_test.go:477-483`
  (`authRequiredBodyRe` ends with `</p>$`, no trailing `\n` in the pattern)
- **What**: Go's default-mode regexp `$` anchor matches at end-of-text OR
  immediately before a single trailing `\n` (Perl-line semantics; RE2 follows
  this in non-`(?m)` mode). The production `errortpl.Template` literal
  (`data-plane/internal/errortpl/template.go:40-45`, gated by T019's
  `NoTrailingNewline` sub-test at `template_test.go:101-109`) ends with
  `</p>` and NO trailing newline. The regex therefore accepts BOTH the
  contract-correct body (`…</p>`) AND a body with one extra trailing LF
  (`…</p>\n`). A DP that emits the extra trailing LF on both responses would
  pass `assertBodyTemplate` and the structural-equality check while not being
  byte-for-byte equal to the Template literal.
- **Implicates**: Test-integrity observation only — not a privacy leak (an
  extra trailing LF reveals nothing about the offer or the destination). The
  exhaustive byte-exact body match is explicitly T068's scope
  (`body_byte_match_test.go`, cited in `contracts/error-template.md` §"Contract
  tests" row 7 and in the ticket §Residue). The structural-equality check
  would still catch any inconsistency between the two responses (one with
  trailing LF, one without).
- **Remediation**: Optional. Tighten the regex to `…\.</p>\z` (using `\z`,
  which matches only at end-of-text, not before a final `\n`) IF you want
  T027 to also gate the trailing-LF property. Leaving the regex as-is is
  defensible because T068 owns the byte-exact match.

#### I3. `dialProxy` duplicated across two test packages
- **Where**: `tests/contract/error-template/auth_required_test.go:301-309`
  and `tests/contract/socks5/demux_test.go:186-194`
- **What**: The `dialProxy` helper is re-implemented in the
  `errortemplate` test package because the original lives in package `socks5`
  in a `_test.go` file, which Go's internal-package rule makes unimportable
  across packages. The T027 copy uses a 30 s deadline (vs T023's 10 s) to
  cover the argon2id auth-fail path; this divergence is correct for each
  ticket's surface but means the two copies can drift independently.
- **Implicates**: Maintenance burden only — not a privacy or correctness
  issue. The T027 copy's deadline is appropriate (argon2id at
  t=3,m=64KiB,p=4 is ~50 ms nominal, more under CI load; 30 s is generous).
- **Remediation**: Optional. If a shared helper is desired, lift `dialProxy`
  into `tests/contract/internal/dpharness` as a non-`_test.go` function
  taking the deadline as a parameter. Out of scope for T027 (surgical-changes
  doctrine).

## Notes

- **Layered defence is load-bearing for this test's correctness.** T027's
  structural-equality check alone cannot catch a DP that emits the SAME
  destination-derived byte in both responses (both requests use the same
  `dest`). The `loginvariants.AssertNoSecrets` corpus scan is the gate that
  catches this; the structural-equality check catches bytes that DIFFER
  between the two cases (token-derived bytes, since the offers differ). The
  ticket explicitly documents this layering (§Analysis must-hold #2 vs #3).
  Confirmed by reading `tests/internal/loginvariants/loginvariants.go:311-319`
  and `:362-381` (nine textual renderings: raw, hex/HEX, 4× base64,
  decimal-slice, decimal-run).
- **Orthogonality with T069 (ref-ID randomness) is correctly scoped.** T027
  masks exactly 16 bytes and does NOT assert the two captured ref-IDs differ;
  a deterministic ref-ID would pass T027 and be caught by T069. This is the
  documented design (ticket §Residue + §Out-of-scope). Confirmed by reading
  the masking loop at `auth_required_test.go:476-481` — it zeroes exactly
  `refIDHexLen` bytes regardless of their value.
- **Orthogonality with T068a (exhaustive header set) is correctly scoped.**
  T027 checks `HasPrefix(wantStatusLine)` and `Contains(wantXStargateError)`
  only; the four-headers-in-declared-order + forbidden-header gate is T068a.
  Confirmed at `auth_required_test.go:669-687`. A DP that emits an extra
  header IDENTICALLY across missing/malformed passes T027 but fails T068a;
  a DP that emits an extra header DIFFERENTLY between the two cases fails
  T027's structural-equality check.
- **`errortpl.Template` (production code, OUT of T027's diff scope) ends
  with NO trailing newline**, gated by T019's `NoTrailingNewline` sub-test
  (`data-plane/internal/errortpl/template_test.go:101-109`). The T027 body
  regex's permissiveness (accepts one extra trailing LF) is therefore
  asymmetric with the actual Template — see I2 above. Not a privacy leak;
  noted for the fixer's awareness when T068 lands.
- **`dpharness` boot content-gates** (out of diff scope but load-bearing for
  the test's SKIP-vs-FAIL behaviour) gate on `listener/socks5.go`,
  `controlclient/server.go`, `cmd/stargate-proxy/main.go`. T027 adds three
  per-test gates on top: `listener/connect.go`, `auth/token.go`,
  `errortpl/render.go`. The test correctly SKIPs (not FAILs) while any is
  absent and becomes a hard FAIL once all land — the tests-first discipline
  per Principle VII.
- **Diff scope.** This review covers ONLY the two files in
  `target/runs/T027.review-diff.patch`. Production data-plane code
  (`listener/connect.go`, `auth/token.go`, `errortpl/render.go`) is
  implemented by T043/T044/T048 and will receive its own redteam gate at
  those tickets' milestones. Findings against production code are explicitly
